## 1. Persona and top jobs-to-be-done

**Persona — "the renovation owner"**: a homeowner or small-remodel coordinator running a kitchen, bath or extension project from a calibrated desktop and a phone on site. She sends room photos and measurements, compares quotes and material lists, files permits, tracks contractor bids and keeps a dated photo record. Family and trades speak English, French, Arabic and Hebrew. The project stays on her own machine: plans, quotes and home photos never go to a hosted service. Approving the wrong quote, filing the wrong permit or confirming a structural change on a colour cue is a real financial and safety loss — legible, named state matters more than a fast screen.

Top jobs:
1. **Describe the job** — send a photo plus dimensions or a question without losing the draft.
2. **Verify before committing** — approve a quote, purchase or permit knowing exact scope, room, supplier, cost and deadline; never decide on colour alone.
3. **Track the work** — tell a requested quote from a stalled permit or a running drawing set by named state; retry, pause or resume without reading a transcript.
4. **Take the console** — take over the bot's plan-drawing or smart-home session for a manual change, then release it with an attributable record.
5. **Name and publish** — keep versioned plans, quotes, material lists and inspection photos, open each in the thread that produced it, and share a reviewed scope of work by link with no login and no leak of another project's data.

## 2. Five concrete UI changes

All new copy is a `lib/i18n.ts` key via `useTranslation()` / `t("key")` (English source; fr/he translations; missing key falls back to English, never blank or raw key). Every colour rides the `docs/UI.md` token map, type uses composite utilities, every class list goes through `cx()`. Bot-, tool- and file-produced values are untrusted text/bytes, never markup.

**(A) Photo-and-measure composer — thread `/app/:botId` (REQ-001, REQ-008).** Extend `ThreadComposer` with an "attach photo / plan" `IconButton` (`RiImageLine`) using the installed `file-upload` component plus the existing reply chip; keep `@bot` mention, Enter-to-send/Shift+Enter-newline, stop while a run is active, and the `awaitingApproval` gate. BoardUI `Button`/`IconButton`/`Tooltip`, icons from `@remixicon/react` as references; surface `bg-background-primary-default`, `rounded-3xl`, `border-border-button-default`, text `text-text-primary`/`text-text-placeholder`, focus `focus-visible:ring-2 focus-visible:ring-border-focus-ring`. Existing RPC `threadsSend` — the photo enters the same draft state, so no new transport. Dimensions, dates and supplier codes stay LTR in `<bdi>`.

**(B) Quote / purchase / permit approval card — thread pending card (REQ-007, REQ-017, REQ-018).** Extend `CardBlock` in `message-blocks.tsx` so "what will happen" dominates: exact scope, room/trade, supplier, cost (integer minor units via `Intl`, ADR-023) and deadline, with an explicit confirm label ("Order <supplier> worktop, <room>, €<amount>, due Friday", not just "Approve"). A structural, electrical or irreversible action pairs `border-border-error-default` + `text-text-error-primary` with a leading icon and the words "Irreversible"/"High cost" — never colour alone. Replace the raw `<button>`/`<input>` with BoardUI `Button`/`Input`; card `bg-background-secondary-default`, `rounded-3xl`, `border-separator-border`, text `text-text-primary`/`text-text-secondary`, 44 px `.boma-target`. Existing RPCs `threadsAnswer` (its `CONFLICT` guard owns a double answer), `threadsReact`. Keep the transcript readable, other threads reachable, focus on the card, decision announced once via the polite live region (§8.9).

**(C) Named renovation run triage — `/app` Activity view (REQ-011, REQ-012, REQ-021, REQ-067).** Group quote, permit, drawing and ordering runs by day with prompt snippet, bot name, a named status chip (queued/leased/running, waiting_input/waiting_takeover, completed/failed/cancelled — §8.9) and duration, with a link back to the message that started it. Working runs sort top and update in place; a failed quote shows one sentence of cause plus one of what to do and a working Retry; queued runs offer Pause/Resume. BoardUI table/chip, `Button`, `IconButton`, `Tooltip`; surfaces `bg-background-primary-default`/`bg-background-secondary-default`, `border-separator-border`, status via `runStatusKey`/`isRetryable` from `lib/run-status.ts`, text + icon, never colour alone. Existing RPCs `runsList`, `runsRetry`, `runsPause`, `runsResume`, `threadsHead`. Background job runs appear here, not in the transcript (§8.4).

**(D) Design / smart-home console takeover — thread right panel (REQ-026, REQ-028, REQ-029).** Reuse `ComputerPanel` for the bot's plan-drawing or smart-home configuration session: starting / running / taken over / released. Keep its named `role="status"` + icon line, held-by marker, `role="alert"` errors and poll loops; an explicit "Take over" `Button` hands input to the owner, "Release" returns it, both attributable. No decorative spinner that outlives its work and no second canvas/viewer library. BoardUI `Button`/`Badge`/`Tooltip`; surfaces `bg-background-primary-default`/`bg-background-secondary-default`, `border-separator-border`, icons `text-foreground-icon-secondary`. Existing RPCs `computerStatus`, `computerOpenScreen`, `computerOpenScreenFrame`, `computerTakeover`, `computerRelease`. Mirror drawer motion in RTL; leave physical plan coordinates untouched; no home data in logs.

**(E) Project board, plan/quote archive and shared scope — `/app/board` (REQ-038, flag-gated), `/app/artifacts` (REQ-036), `/p/:slugToken` (REQ-037).** Reuse `BoardScreen`: retitle its four `COLUMNS` as measured → quoted → in progress → signed off, each card with key, title, assignee bot and comment count; the focus-trapped detail dialog shows description, attached runs, move buttons and a comment form; replace its raw `<input>`/`<select>`/`<textarea>` with BoardUI `Input`/`Select`; a 404 keeps the route absent, not locked (§8.6). Existing RPCs `boardsGet`, `ticketsCreate`, `ticketsMove`, `ticketsComment`. In the library, keep versioned plans, quotes, material lists and inspection photos via `artifactsListSpace`, `artifactsGet`, `artifactsListVersions`, `artifactsRemove`, in a bounded frame with untrusted-byte rules. Reuse `SharedPageScreen` for a reviewed scope of work with no session and no chrome beyond a small robot-cat footer; unknown, revoked and expired tokens render one identical "not available" document — same words, shape and timing.

## 3. Accessibility, i18n and RTL

- Every visible string is a `lib/i18n.ts` key via `t("key")` (English source, fr/he translations; missing key falls back to English, never blank or raw key). No string hardcoded in JSX.
- `DirectionProvider` (`@/components/foundations/direction/direction`) takes an explicit BCP 47 locale; the boot script writes `lang`/`dir` together. Use logical utilities (`ms`/`me`, `ps`/`pe`, `text-start`/`text-end`, `border-s`/`border-e`) and `useDirection()` to mirror the rail, board columns and drawer motion in RTL; arrows flip. Dimensions, dates, supplier codes, money and URLs stay LTR in `<bdi>`/`dir="auto"`, formatted with `Intl`. Measured geometry and artwork never mirror.
- WCAG 2.2 AA gate: zero critical/serious axe findings in light, dark and RTL; ≥44 px `.boma-target`; token-driven visible focus; a full keyboard path (decision, attach, retry/pause, takeover/release, board move, version select, dialog); status and decision are text + icon, never colour alone; 360 px width; `prefers-reduced-motion`; no animation on streaming content. Tables carry `<caption>` and `<th scope>`; the detail dialog keeps its focus trap and Escape.
- A decision is announced once via the polite live region — the transcript is not a live region, so tokens are not read aloud. The uniform unavailable screen is announced in identical text — no leak through the accessibility tree. Error copy is one sentence of what happened plus one of what to do — no plan id, quote, supplier, stack trace or provider text on screen (correlation id behind "details" only, §8.9). The robot-cat mark stays unchanged.
