## 1. Persona and top jobs-to-be-done

**Persona — "the facilities lead"**: building-operations manager at a self-hosted campus, clinic or plant, running incident intake, preventive maintenance, safety inspections, energy/HVAC monitoring and contractor dispatch from a calibrated desktop and a phone between rounds. Staff speak English, French, Arabic and Hebrew. Building data, badge records, BMS credentials and vendor contracts never leave the site. She is not a technologist; approving the wrong work order, dispatching a contractor to the wrong floor, or signing a fire-safety inspection on a colour cue is a real safety and compliance loss — ambiguity is worse than latency.

Top jobs:
1. **Triage** — tell a reported incident from a routine request by exact asset, location, priority and named state; never decide on colour alone.
2. **Authorise** — approve a work order or dispatch knowing the asset, floor, vendor and exact consequence; treat safety-critical or irreversible actions as explicit, not implicit.
3. **Take the console** — take over the bot's BMS/HVAC/access-control session for a maintenance or safety action, then release it with an attributable record.
4. **Report from anywhere** — send an incident with a photo or asset tag and reply in-thread without losing the draft.
5. **Name and record the work** — say out loud which maintenance and inspection runs are working, paused or terminal, keep versioned O&M manuals and asset records, and publish a reviewed inspection report by link with no login and no leak of another site's data.

## 2. Five concrete UI changes

All new copy is a new `lib/i18n.ts` key via `useTranslation()` / `t("key")` (English source; fr/he translations; a missing key falls back to English, never a blank or the raw key). Every colour rides the `docs/UI.md` token map, type uses composite utilities, every class list goes through `cx()`. Bot- and tool-produced values are untrusted text/bytes, never markup.

**(A) Work-order / dispatch approval card — thread `/app/:botId` pending card (REQ-007, REQ-017).** Extend `CardBlock` in `message-blocks.tsx` so the "what will happen" sentence dominates: asset tag, floor/room, priority, vendor and consequence, with an explicit label ("Dispatch <vendor> to <floor> for <asset>", not just "Approve"). A safety-critical or irreversible action (fire panel, lockdown, energise) pairs `border-border-error-default` + `text-text-error-primary` with a leading icon and the words "Safety-critical" — never colour alone. BoardUI `Button`, `Badge`, `Tooltip`; card `bg-background-secondary-default`, `rounded-3xl`, `border-separator-border`, text `text-text-primary`/`text-text-secondary`, focus `focus-visible:ring-2 focus-visible:ring-border-focus-ring`. Existing RPCs: `threadsAnswer` (its `CONFLICT` guard owns a double answer), `threadsReact`. Transcript stays readable, other threads reachable, focus lands on the card, decision announced once via the polite live region (§8.9); no new transport.

**(B) Supervisory console takeover panel — thread right panel (REQ-026, REQ-028, REQ-029, REQ-030).** Reuse `ComputerPanel` for the bot's BMS/HVAC/access-control session: starting / running / taken over / released. Keep its named `role="status"` + icon line, held-by marker, `role="alert"` errors and poll loops; a clear "Take over" `Button` hands input to the facilities lead, "Release" returns it. Status is text + icon, never a decorative spinner that outlives its work, and no second viewer or canvas library. BoardUI `Button`, `Badge`, `Tooltip`; surfaces `bg-background-primary-default`/`bg-background-secondary-default`, `border-separator-border`, icons `text-foreground-icon-secondary`, 44 px `.boma-target`. Existing RPCs: `computerStatus`, `computerOpenScreen`, `computerOpenScreenFrame`, `computerTakeover`, `computerRelease`.

**(C) Incident-report composer — thread `/app/:botId` composer (REQ-001, REQ-008).** Extend `ThreadComposer` with an "attach photo / asset tag" `IconButton` (`RiImageLine`) using the installed `file-upload` component and the existing reply-chip pattern; keep `@bot` mention, Enter-to-send / Shift+Enter-newline, stop while a run is active, and send disabled while an approval is pending. BoardUI `IconButton`, `Tooltip`; icons from `@remixicon/react` as references, `text-foreground-icon-primary`, token focus ring. Existing RPC `threadsSend`; the attachment enters the same draft state, so no new transport. Asset tags, floor codes and dates stay LTR in `<bdi>`.

**(D) Work-order run triage — `/app` Activity view (REQ-011, REQ-012, REQ-021, REQ-067).** Follow `ActivityScreen`: group inspection, maintenance and energy runs by day with prompt snippet, bot name, a named status chip (queued/leased/running, waiting_input/waiting_takeover, completed/failed/cancelled — §8.9) and duration, with a link back to the message that started it. Working runs sort to the top and update in place; a failed inspection gets one sentence of cause, one of what to do and a working Retry, never a bare spinner. BoardUI table/chip, `Button`, `IconButton`, `Tooltip`; surfaces `bg-background-primary-default`/`bg-background-secondary-default`, `border-separator-border`, status text + icon. Existing RPCs: `runsList`, `runsRetry`, `runsPause`, `runsResume`, `threadsHead`.

**(E) Work-order board, O&M library and inspection report — `/app/board` (REQ-038, flag-gated), `/app/artifacts` (REQ-036), `/p/:slugToken` (REQ-037).** Reuse `BoardScreen`: retitle its four `COLUMNS` as reported → triaged → scheduled → done, each card with key, title, assignee bot and comment count; the focus-trapped detail dialog shows description, assigned bot, move buttons and a comment form with attached runs. A 404 keeps the route absent, not locked (§8.6). Replace its raw `<input>`/`<select>`/`<textarea>` with installed BoardUI `Input`/`Select` to honour the one-system rule; surfaces `bg-background-primary-default`, `border-separator-border`, `text-text-primary`/`text-text-secondary`, classes merged with `cx()`. Existing RPCs: `boardsGet`, `botsList`, `ticketsCreate`, `ticketsMove`, `ticketsComment`. In the library, keep versioned O&M manuals, floor plans and asset records via `artifactsListSpace`, `artifactsGet`, `artifactsListVersions`, `artifactsRemove`, keeping the bounded frame and untrusted-byte rules. Reuse `SharedPageScreen` to publish a reviewed inspection report with no session and no chrome beyond a small robot-cat footer; unknown, revoked and expired tokens render one identical "not available" document — same words, shape and timing. Transport (CONFIRMED): `GET /api/v1/pages/shared/{token}`.

## 3. Accessibility, i18n and RTL

- Every visible string is a `lib/i18n.ts` key via `t("key")` (English source, fr/he translations; a missing key falls back to English, never blank or raw key). No string in JSX.
- `DirectionProvider` (`@/components/foundations/direction/direction`) takes an explicit BCP 47 locale; the boot script writes `lang`/`dir` together. Use logical utilities (`ms`/`me`, `ps`/`pe`, `text-start`/`text-end`, `border-s`/`border-e`) and `useDirection()` to mirror the rail, drawer motion and board columns in RTL; arrows flip. Asset tags, floor codes, dates, URLs and OTP digits stay LTR in `<bdi>`/`dir="auto"`, formatted with `Intl`. Measured geometry and artwork are never mirrored.
- WCAG 2.2 AA gate: zero critical/serious axe findings in light, dark and RTL; ≥44 px `.boma-target`; token-driven visible focus; a full keyboard path (decision, takeover/release, attach, retry/pause, board move, version select, dialog); status and decision are text + icon, never colour alone; 360 px width; `prefers-reduced-motion`; no animation on streaming content. Tables carry `<caption>` and `<th scope>`; the detail dialog keeps its focus trap and Escape.
- A decision is announced once via the polite live region — the transcript is not a live region, so tokens are not read aloud. The uniform unavailable screen is announced in identical text — no leak through the accessibility tree. Error copy is one sentence of what happened plus one of what to do — no asset tag, floor plan, badge record, stack trace or provider text on screen (correlation id behind "details" only, §8.9). The robot-cat mark stays unchanged.
