## 1. Persona and top jobs-to-be-done

**Persona — "the account owner"**: a rep or small-team lead at a firm running Boma Bot on its own
machine. She directs bots to enrich contacts, draft outreach and prepare proposals, reviews the result
on desktop and phone, and serves English, French, Arabic and Hebrew colleagues. Contact PII, deal
values and customer names never leave the firm; no cloud. She is measured on attribution and
reversibility, not speed: the wrong proposal or an unapproved discount is a real loss — ambiguity is
worse than latency. The robot-cat mark is the only identity art; no CRM vendor logo is borrowed.

Top jobs:
1. **Approve a customer-facing step** — discount, proposal or contract send — knowing the exact
   account, amount and consequence; never by colour alone.
2. **Verify before commit** — take over the bot's CRM data-entry session to check contact details,
   then release with an attributable record.
3. **Direct from anywhere** — send an account brief, attach a contract, reply in-thread.
4. **Name the work** — state every outreach/import run out loud (§8.9), retry only failures,
   pause/resume queued work, with a link to the message that started it.
5. **Keep and share a record** — a versioned proposal library and a compiled account summary shared
   by link with no login, never leaking another account's data.

## 2. Five concrete UI changes

All new copy is an i18n-catalogue key via `useTranslation()`'s `t(key)`; no string in JSX. Every class
list goes through `cx()`; every colour rides the `docs/UI.md` token map. Bot bytes are untrusted text or
images, never markup; keep contact names, e-mail and deal values out of logs.

**A. Customer-facing decision card — thread `/app/:botId` (REQ-007, REQ-017).** Extend `CardBlock` in
`message-blocks.tsx`: make the "what will happen" sentence dominant — account, amount, channel,
consequence — with an explicit confirm label ("Send the 10% discount proposal to <account>", not just
"Approve"). Irreversible/customer-facing steps pair `border-border-error-default` +
`text-text-error-primary` with a leading icon and the words "Customer-facing" — never colour alone.
Replace the card's raw buttons/input with BoardUI `Button`/`Input`, plus `Badge`/`Tooltip`; card
`bg-background-secondary-default`, `rounded-3xl`, `border-separator-border`, text
`text-text-primary`/`text-text-secondary`, focus `focus-visible:ring-2 focus-visible:ring-border-focus-ring`.
Existing RPCs: `threadsAnswer` (the `CONFLICT` guard already owns a double answer); `threadsReact`.
Transcript stays readable, other threads reachable, focus lands on the card; announce once via the
polite live region (§8.9); the transcript is not a live region.

**B. CRM entry canvas with takeover — thread right panel (REQ-026, REQ-028, REQ-029).** Reuse
`computer-panel.tsx` for a bot updating a contact or preparing a proposal: starting / running / taken
over / released. A "Take over" `Button` hands input to the account owner to verify contact details
before commit; "Release" returns it; status is text + icon. BoardUI `Drawer`, `Spinner`, `Skeleton`,
`Button`, `Badge`; surfaces `bg-background-secondary-default`/`bg-background-full`, hairline
`border-separator-border`, icon `text-foreground-icon-primary`, 44 px `.boma-target`. Existing RPCs:
`computerStatus`, `computerOpenScreen`, `computerOpenScreenFrame`, `computerTakeover`, `computerRelease`.
No decorative spinner that outlives its work; no second viewer or canvas library.

**C. Account-brief composer — `/app/:botId` composer (REQ-001, REQ-008).** Extend `thread-composer.tsx`
with an "attach contract" `IconButton` (`RiFileTextLine`) using the installed `file-upload` component
and the existing reply-chip pattern; keep `@bot` mention, Enter to send / Shift+Enter new line, stop
while a run is active, send disabled while an approval is pending. BoardUI `IconButton`, `Tooltip`;
icons from `@remixicon/react` as references, `text-foreground-icon-primary`, focus token ring.
Existing RPC `threadsSend`; the attachment enters the same draft state, so no new transport. Contact
names, amounts and dates stay LTR in `<bdi>`.

**D. Outreach/import monitor — `/app` Activity view (REQ-011, REQ-012, REQ-021, REQ-067).** Reuse
`ActivityScreen`: group outreach and import runs by day with prompt snippet, bot name, a named status
chip (queued/leased/running, waiting_input/waiting_takeover, completed/failed/cancelled — §8.9),
duration and a link back to the starting message. Working runs sort to the top and update in place; a
failed import gets one sentence of cause plus one of what to do and a working Retry, never a bare
spinner; queued work can be paused/resumed. BoardUI table/chip, `Button`, `IconButton`, `Tooltip`;
surfaces `bg-background-primary-default`/`bg-background-secondary-default`, `border-separator-border`,
status text + icon. Existing RPCs: `runsList`, `runsRetry`, `runsPause`, `runsResume`, `threadsHead`.

**E. Proposal library, deal pipeline and account-summary link — `/app/artifacts` (REQ-036), `/app/board`
(REQ-038, feature-flagged), `/p/:slugToken` (REQ-037).** Reuse `ArtifactsGrid` as a versioned proposal
library: name, type icon, size, owner bot, updated time, filter by type/bot, search by name, version
chain and "open in thread". Replace its raw `<select>`/`<input>` with installed BoardUI `Select`/`Input`
to honour the one-system rule; keep the bounded frame and untrusted-byte rules. Retitle the flag-gated
board columns as lead → qualified → proposal → won via `boardsGet`, `ticketsCreate`, `ticketsMove`,
`ticketsComment` — a deal is a ticket with an assignee bot; a 404 keeps the route absent, not locked
(§8.6). Publish a compiled account summary at `/p/:slugToken` with no chrome beyond a small robot-cat
footer; unknown, revoked and expired tokens render one identical "not available" document — same words,
shape and timing. Register RPCs: `artifactsListSpace`, `artifactsGet`, `artifactsListVersions`,
`artifactsRemove`; shared transport (CONFIRMED): `GET /api/v1/pages/shared/:token`.

## 3. Accessibility, i18n and RTL

- Every visible string goes through `t(key)` (English source; fr/he translations; a missing key falls back to English, never a blank or the raw key). No string in JSX.
- `DirectionProvider` (`@/components/foundations/direction/direction`) gets an explicit BCP 47 locale;
  the boot script writes `lang`/`dir` together. Logical utilities throughout (`ms`/`me`, `ps`/`pe`,
  `text-start`/`text-end`, `border-s`/`border-e`). Mirror the rail, drawer motion and pipeline columns
  via `useDirection()`; flip arrows. Contact names, e-mail, deal values, dates, URLs and OTP digits
  stay LTR in `<bdi>`/`dir="auto"`, formatted with `Intl`. Measured geometry/artwork are never mirrored.
- WCAG 2.2 AA: zero critical/serious axe findings in light, dark and RTL; 44 px `.boma-target`;
  token-driven visible focus; full keyboard path (decision, takeover/release, attach, retry/pause,
  pipeline move, version select); status and decision are text + icon, never colour alone; 360 px
  width; `prefers-reduced-motion`; no animation on streaming content.
- The customer-facing decision is announced once via the polite live region — the transcript is not a
  live region, so streaming tokens are not read aloud. The uniform unavailable screen is announced in
  identical text — no leak through the accessibility tree. Error copy is one sentence of what happened
  plus one of what to do; no contact name, e-mail, deal value, stack trace or provider text on screen
  (correlation id behind "details"). The robot-cat mark stays unchanged.
