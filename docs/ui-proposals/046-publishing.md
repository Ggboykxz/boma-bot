## 1. Persona and top jobs-to-be-done

**Persona — "the managing editor"**: an editor at a newspaper, journal, magazine or independent publishing house who commissions stories, moves manuscripts through editing and proofing, and schedules publication to a web edition or newsletter. She works in English, French and Arabic, between a newsroom desktop and a phone on the proofing floor. Boma Bot runs on the publisher's own machine: drafts, author identities, subscriber lists, embargo times and rights terms never leave it. A story published to the wrong channel, before its embargo, or from a stale proof is a real reputational and legal event, so legible state and an explicit "what will happen" matter more than a fast screen. The robot-cat mark is the only identity art — no publisher, masthead or imprint logo is borrowed.

Top jobs:
1. **See the desk pulse** — one band of open submissions, due dates, embargo state and active editorial runs on the thread, without hunting the rail.
2. **Authorise publication** — review a bot-proposed publish, embargo lift or newsletter send knowing the exact headline/slug, destination, audience, time and consequence; never approve on colour alone.
3. **Run the copy desk** — move a piece from commissioned through drafting, editing and proofing to published, keeping attached runs and comments with it.
4. **Name run state** — state every ingest, OCR, layout and distribution run out loud using the §8.9 vocabulary; retry only failures, pause/resume queued work.
5. **Keep versions and publish a reader** — hold manuscripts, galleys, proofs and issue PDFs as a version chain, open each in the thread that produced it, and publish a compiled article or issue to a reader by link with no login or leakage.

## 2. Five concrete UI changes

All new copy is a `lib/i18n.ts` key via `useTranslation` / `t(locale, key)` (English source, fr/he translations, a missing key falls back to English — never blank or the raw key). Every colour rides the `docs/UI.md` token map, type uses composite utilities, and every class list goes through `cx()`.

**(a) Desk-status strip — screen `/app/:botId` (thread header).** A compact, read-only band above the transcript: named chips for open submissions, next due date, embargo state and active editorial runs, plus a small volume trend using `chart-1`…`chart-5` tokens with `-active` variants. Components: BoardUI `Chip`/`Badge` (`components/base/badges/chip.tsx`), `Tooltip`, `IconButton` (icons from `@remixicon/react` passed as references). Tokens: surface `bg-background-secondary-default`, hairline `border-separator-border`, text `text-text-primary`/`text-text-secondary`, icons `text-foreground-icon-secondary`, type `text-caption-1-semibold`. RPCs (CONFIRMED): `botsGet`, `threadsHead`, `threadsMessages`, `runsList`. Bot-produced values are untrusted text, never HTML; author identities and subscriber counts stay out of logs and hover-only tooltips. Measured chart geometry stays LTR.

**(b) Publication approval card — screen `/app/:botId` (pending card, REQ-007/REQ-017).** Make the "what will happen" sentence dominant: exact headline/slug, destination channel, audience, embargo time and consequence, with an explicit confirm label ("Publish 'River levels fall' to the web edition at 06:00", not just "Approve"). A high-impact action (publish, embargo lift, newsletter send) pairs `border-border-error-default` + `text-text-error-primary` with a leading icon and the words "High impact" — never colour alone. Components: `Button`, `Badge`, `Tooltip`; card surface `bg-background-primary-default`, `rounded-3xl`, `border-border-button-default`, focus `focus-visible:ring-2 focus-visible:ring-border-focus-ring`. RPCs (CONFIRMED): `threadsAnswer` (keep the `CONFLICT` guard for double answers), `threadsReact`. Reuse `ThreadComposer`'s `awaitingApproval` prop so the transcript stays readable and other threads reachable; the decision is announced once through the polite live region (§8.9), the transcript is not a live region.

**(c) Copy-desk board — screen `/app/board` (REQ-038, feature-flagged).** Reuse `BoardScreen`: retitle the four `COLUMNS` as commissioned → drafting → editing → proofing → published; each card shows the slug/headline, assignee bot and last comment, and the detail panel shows the attached runs. Prefer installed BoardUI `Input`/`Select` over the screen's raw fields, merged with `cx()`; tokens `bg-background-primary-default`, `border-separator-border`, `text-text-primary`/`text-text-secondary`, focus via the focus-ring token. RPCs (CONFIRMED): `boardsGet`, `botsList`, `ticketsCreate`, `ticketsMove`, `ticketsComment`. A flag-off `404` keeps the route absent, not locked (§8.6). Status is text + icon, never colour alone.

**(d) Editorial-run triage — activity view (REQ-011/REQ-012/REQ-067).** Follow `ActivityScreen`: group ingest, OCR, layout and distribution runs by day, with named status chips (queued, leased, running, waiting_input, waiting_takeover, completed, failed, cancelled) via `runStatusKey` as text + icon; pause/resume queued work, retry only `failed`. BoardUI `Button`, `Chip`; tokens `bg-background-primary-default`, `border-border-button-default`, `text-text-primary`/`text-text-secondary`, and `border-border-error-default` + `text-text-error-primary` + `text-foreground-icon-error` on the error row. RPCs (CONFIRMED): `runsList`, `runsRetry`, `runsPause`, `runsResume`. Working runs sort to the top and update in place. Run/card arrivals use the existing `notifications.*` policy surface (REQ-064).

**(e) Manuscript library and shared reader — screens `/app/artifacts` and `/p/:slugToken` (REQ-036/REQ-037/REQ-039).** In `ArtifactsGrid`, name manuscripts, galleys, proofs, style sheets and issue PDFs by type, filter by type/bot, search by name, show the version chain and "open in thread". Content is untrusted — render as data, never inject artifact HTML into the document. Components: `Input`, `Select`, `Chip`, `Button`; tokens `text-text-primary`/`text-text-secondary`/`text-text-tertiary`, `bg-background-primary-default`, `border-border-button-default`. RPCs (CONFIRMED): `artifactsListSpace`, `artifactsGet`, `artifactsListVersions`. Reuse `SharedPageScreen`'s block renderer and its safe-link/safe-image walls: publish a compiled article or issue reader with no session and no product chrome beyond a small footer with the robot-cat mark; unknown, revoked and expired tokens render one identical "not available" screen — same words, shape and timing. Transport (CONFIRMED): `GET /api/v1/pages/shared/{token}`; `noindex`/`no-referrer` and its own sandbox/CSP stay backend concerns (REQ-039). Keep the robot-cat empty state when nothing is filed.

## 3. Accessibility

WCAG 2.2 AA gate: zero critical/serious axe findings in light, dark and RTL; a keyboard-only path for every primary flow (approve, board moves, pause/resume, retry, filters); visible `focus-visible:ring-2 focus-visible:ring-border-focus-ring`; ≥44 px `.boma-target` on proofing-floor controls; 360 px width; `prefers-reduced-motion` honoured; no animation on streaming content. Run status and publication state are text + icon using the exact §8.9 vocabulary — no colour-only embargo or error cues. Tables carry `<caption>` and `<th scope>`. Focus lands on a pending card; the uniform unavailable screen is announced in identical text — no leak through the accessibility tree. Error copy is one sentence of what happened plus one of what to do — no author, subscriber, embargo, rights detail, stack trace or provider text on screen (correlation id behind "details" only, §8.9).

## 4. i18n and RTL

English is the source catalogue, fr/he the translations; a missing key falls back to English — never blank or the raw key. `DirectionProvider` (`@/components/foundations/direction/direction`) gets an explicit BCP 47 locale; the boot script writes `lang` and `dir` together. RTL mirrors the board's columns, the rail and the drawer motion via `useDirection()`; arrows flip. Logical utilities throughout (`ms`/`me`, `ps`/`pe`, `text-start`/`text-end`, `border-s`/`border-e`). Slugs, URLs, ISO dates, times, embargo timestamps and OTP digits stay LTR in `<bdi>`/`dir="auto"`; article body direction follows its own locale, never the interface's. Measured chart geometry is never mirrored. Formatting application data is separate from layout direction.
