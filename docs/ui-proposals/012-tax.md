# UI proposal 012 — tax advisory practice

Status: PROPOSAL (GUESS where the spec is silent). Sector specialist #012. Read-only on product code.
Grounding: `docs/UI.md`, `spec/08-ui-ux.md`, `apps/web/lib/api/rpc.ts`, and two components —
`apps/web/components/thread/thread-composer.tsx`, `apps/web/components/shell/bot-rail.tsx`.
Charter: Boma Bot / robot-cat identity only; no upstream/OpenBot brand, code, wording or assets;
BoardUI tokens only, no raw palette/hex, `cx()` to merge; one design system; self-hosted, no SaaS —
client financial data never leaves the firm's own machine.

## 1. Persona and top jobs-to-be-done

**Persona — Mrs. Lina, tax advisor in a 3-person practice.** She handles individual and small-business
clients through a filing season of hard deadlines and frequent interruptions, with a multilingual
client panel (French, English, Arabic, Hebrew). A wrong figure or an irreversible filing is a
client-harm and compliance event, so a wrong click is worse than a slow screen. Boma Bot is the
firm's assistant on its own machine — no cloud, no third-party SaaS, no client data off-site. She is
not a technologist; she must be able to name out loud what any proposed action will do before it runs.

Top jobs:
1. **Prepare** — before a client call, see the bot's one-screen summary: open items, missing
   documents, next filing deadline — without hunting through the rail.
2. **Capture** — dictate or type notes and figures fast, without losing the draft to a stray Enter,
   and keep amounts readable and exact.
3. **Verify** — review a bot-proposed filing, figure change or client message and be certain what
   will happen before approving; never approve by colour alone.
4. **Track deadlines** — across the season, find upcoming due dates and paused follow-ups, snooze
   non-urgent ones, and know at a glance which runs are still working.
5. **Hand over and share** — pass an open client thread to a colleague/bot at a clean, attributable
   handover, and share a compiled summary with one client by link without exposing another's data.

## 2. Five concrete changes

All strings are new keys in `lib/i18n.ts` through `t(locale, key)`; no hardcoded copy. All reuse
BoardUI components under `apps/web/components/` and the semantic tokens in `docs/UI.md`.

**(a) Filing-deadline context strip — screen `/app/:botId` (thread header).**
A compact, read-only band above the transcript: chips for "next deadline", "missing documents",
"open questions", each with a `Tooltip` that expands the detail. Built from BoardUI `Badge`/`Chip`
(`components/base/badges/chip.tsx`), `Tooltip`, `IconButton`; surfaces `bg-background-secondary-default`,
hairline `border-separator-border`, text `text-text-secondary` / `text-text-primary`, icons
`text-foreground-icon-secondary`, type `text-caption-1-semibold`. RPCs already available: `botsGet`,
`threadsHead`, `threadsMessages`. Bot-produced content is untrusted — render as text, never HTML.

**(b) Filing approval card — screen `/app/:botId` (pending card, REQ-007 / REQ-017).**
Make the "what will happen" sentence the dominant line; add an explicit consequence summary and a
distinct confirm label ("File return", not just "Approve"). High-impact or irreversible cards use
`border-border-error-default` + `text-text-error-primary` **plus** an icon and the word "High
impact" — never colour alone. BoardUI `Button`, `Badge`, `Tooltip`; card surface
`bg-background-primary-default`, `rounded-3xl`, `border-border-button-default`. RPCs: `threadsAnswer`,
`threadsReact`. The card is announced once through the polite live region (spec §8.9); the transcript
is not a live region.

**(c) Exact-figures composer — screen `/app/:botId` (composer, REQ-001).**
Extend `ThreadComposer` with an attach `IconButton` (`RiAttachmentLine`) and a visible "review
figures" chip while a run awaits input; keep Enter-to-send / Shift+Enter-newline exactly as today,
and keep send disabled while an approval is pending. Amounts pasted into the field stay LTR and are
isolated in `<bdi>` so a figure never mirrors in RTL. BoardUI `IconButton` + `Tooltip` from
`components/base/buttons/icon-button.tsx`; focus `focus-visible:ring-2 focus-visible:ring-border-focus-ring`,
44 px `.boma-target`, `text-foreground-icon-primary`. RPC: `threadsSend` — text enters the same
`value` state, so no new transport.

**(d) Client-share review — screens `/app/artifacts/:artifactId` and `/p/:slugToken` (REQ-036 / REQ-037).**
Before a compiled summary is shared, a review panel lists exactly which threads/artifacts and which
version are included, with a named status chip and an explicit "what the client will see" sentence.
BoardUI `Button`, `Badge`, `Tooltip`, `Select` for the version; tokens `bg-background-primary-default`,
`border-separator-border`, `text-text-secondary`, `text-text-error-primary` for a conflict plus
text+icon. RPCs: `artifactsGet`, `artifactsListVersions`, `artifactsListSpace`. Unknown or revoked
tokens show the uniform "not available" screen (§8.8); artifact content renders as text, never HTML
(§8.5), so one client's data cannot leak to another.

**(e) Deadline triage in the rail — screen `/app` shell left rail (REQ-009 / REQ-011 / REQ-012).**
Replace the unread count's bare number with `Counter` + a named `Chip` status ("Due Friday",
"Awaiting documents", "Working", "Snoozed till 16:00"), with a keyboard-focusable `Tooltip` for due
detail. Group the snoozed shelf by due time using the installed `date-calendar`/`date-picker` if a
picker is added. BoardUI `Counter`, `Chip`, `IconButton`; tokens `text-text-primary`,
`text-text-secondary`, `bg-background-tertiary-default`, `animate-number-fade` for the count per
`docs/UI.md`. RPCs: `threadsMarkRead`, `threadsMarkUnread`, `threadsSnooze`, `threadsUnsnooze`,
`runsList`.

## 3. Accessibility, i18n and RTL

- New labels go in `lib/i18n.ts` (English source; French/Hebrew translations; a missing key falls back
  to English, never a blank or the key). No string in JSX.
- `DirectionProvider` sets locale/direction; the boot script writes `lang`/`dir`. Use logical utilities
  (`ms`/`me`, `ps`/`pe`, `text-start`/`text-end`, `border-s`/`border-e`). Mirror the reassign/back
  arrows via `useDirection()`; keep currency amounts, dates, tax IDs, client IDs and URLs LTR in
  `<bdi>`/`dir="auto"` — a figure must never mirror with the layout.
- WCAG 2.2 AA gate: zero critical/serious axe findings in light, dark and RTL; 44 px targets via
  `.boma-target`; visible token-driven focus; full keyboard path (card decisions, reassign, snooze,
  version select); status conveyed by text + icon, not colour; 360 px width; `prefers-reduced-motion`.
- Client confidentiality: self-hosted, no SaaS — nothing confidential leaves the firm's machine.
  Error copy is one sentence of what happened plus one of what to do — no amounts, IDs, stack traces
  or provider text on screen (correlation id behind "details" only, §8.9). Nothing confidential sits
  in a hover-only tooltip, and no client data is written to logs.

## 5. Highest-impact first slice

**Change (b), the filing approval card.** It is the smallest, highest-value step: one screen, no new
transport (`threadsAnswer` already exists), no new component (BoardUI `Button`/`Badge`/`Tooltip` are
installed), and it directly reduces the risk of an irreversible, ambiguous filing decision.
Test-first: write `REQ-007 ... names the exact action` and `REQ-017 ... gates the effect`, and extend
`spec/golden/ui/REQ-007-pending-card.json` first; ship only the dominant consequence sentence, the
explicit confirm label, and the text+icon high-impact marker. Defer (a), (c), (d), (e) until the owner
assigns REQ ids and approves.
