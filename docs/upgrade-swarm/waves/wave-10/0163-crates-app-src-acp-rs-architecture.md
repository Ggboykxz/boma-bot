# 0163 — crates/app/src/acp.rs — architecture lens

- Target: `before-m5` (v0.3.0-rc5), module `crates/app/src/acp.rs` (324 lines, the ACP stdio transport for REQ-061). Proposal for **v0.4.0**.
- READ-ONLY review; no product code edited. Anchors: `spec/01-requirements.md:620-634` (REQ-061), `docs/adr/030-local-acp-agents.md` (decisions 1, 3, 4, 5, 6), `crates/app/src/acp_provider.rs` (the only consumer), `AGENTS.md` Rust standards. Claims marked CONFIRMED (read this session) or GUESS (inferred).

## Structure today

`AcpSession` is a hand-rolled JSON-RPC 2.0 client owning `Child`, `ChildStdin`, `BufReader<ChildStdout>`, a `next_id: u64`, a `Duration`, and `Option<Box<dyn PermissionDecider>>`. `PermissionDecider::decide(&mut self, &Value) -> Value` is async and returns the raw `result` object. Public surface: `spawn` (sync), `set_permission_decider`, `drain_stderr`, `initialize`, `session_new`, `session_prompt`, `session_close`, `shutdown`; private `send`, `read_line_bounded`, `request`. Every error is `AppError::Unavailable`. One subprocess per turn is owned by `AcpProvider::turn_inner`, which wraps `session_prompt` in a 600 s timeout, spawns a stderr drain, and does best-effort close/shutdown. The module has no tests of its own; wire coverage lives in `crates/testkit`. CONFIRMED.

## Confirmed observations

1. **Two divergent read loops.** `request()` (:146-179) and `session_prompt()` (:235-307) each reimplement bounded read + timeout + JSON parse + id matching. `request()` drops every message whose `id` differs — including `session/update` and `session/request_permission` during `initialize`, `session/new` or `session/close`; `session_prompt()` alone handles notifications, and only `agent_message_chunk`. CONFIRMED. So a permission request arriving during setup is silently discarded, and a capability-driven client call is unanswerable.
2. **Free-form `Value` everywhere.** Messages are built with `json!` and read through `.get()` chains with `unwrap_or` fallbacks (:186-225, :264-304). ADR-030 decision 6 promises "strict structs, no free-form passthrough"; the implementation does not meet that promise. CONFIRMED.
3. **Handshake invariant is documented but not enforced.** The `initialize` doc (:184-185) says it fails on a protocol version other than 1, but the method returns the raw response unchecked; the provider ignores it. `clientCapabilities` (:191-194) advertises `fs.readTextFile`, `fs.writeTextFile` and `terminal` although no client-side handler exists here — any such agent request becomes a dropped notification. CONFIRMED (code); GUESS that real executors actually invoke them.
4. **The read pump blocks on the permission decider.** `decide()` is awaited inline (:267-270); the provider's decider polls a card every 500 ms for up to **24 h** (`acp_provider.rs:61,173-198`), while the outer prompt timeout is 600 s (`DEFAULT_PROMPT_TIMEOUT`). CONFIRMED. Consequence: updates stop streaming while a card is pending, the outer timeout wins and abandons the card, and no `session/cancel` is ever sent — `shutdown()` only drops stdin (REQ-061's "crashed executor" criterion is handled at the worker layer, not here). CONFIRMED.
5. **Agent ids assumed numeric.** `session/request_permission` uses `as_u64().unwrap_or(0)` (:266); JSON-RPC permits string ids, which would be answered with id `0` and mis-correlate. CONFIRMED; likelihood GUESS.
6. **Lossy errors and no local tests.** All failures collapse to `Unavailable`, so the worker cannot distinguish missing binary, handshake refusal, timeout, line-cap violation, malformed JSON or an agent error code. `session_close` swallows all. No `#[cfg(test)]` in the file, despite `read_line_bounded` being a parser of an external wire format. CONFIRMED.

## Proposals (v0.4.0)

1. **One bidirectional message pump.** Replace the two loops with a single `read_dispatch()` that classifies each frame as `Response(id) | Notification(method) | AgentRequest(id, method)` and routes it to a small handler table; `request()` and `session_prompt()` become thin wrappers that loop until their id arrives while the dispatcher keeps streaming updates and answering agent requests. Fixes observation 1 and gives one place for timeout/parse/cap. Risk: changes interleaving and notification handling during setup — a behavior change to verify against the committed stub golden and to record in `docs/PARITY.md`; gate on extended wire tests, never weaken them.

2. **Typed protocol model, forward-compatible inbound.** Introduce `JsonRpcEnvelope`, `InitializeParams/Result`, `SessionNewResult`, `SessionNotification`, `PermissionParams`, `PermissionOutcome` with serde; build outbound messages from structs instead of `json!`. Use `#[serde(deny_unknown_fields)]` only where we own the shape; accept unknown fields on agent→client frames so future ACP fields do not break us. Validate `protocolVersion == 1`, capture the negotiated version and `sessionId` in the session, and support string ids (`Id::Num | Id::Str`). Risk: over-strict structs reject real executors; mitigate with an "unknown method/field → warn and skip" default and one wire test per executor before removing any loose path. This closes the ADR-030 decision-6 gap.

3. **Honest capability negotiation.** Either (a) drop `fs`/`terminal` from `clientCapabilities` so agents cannot request unimplemented client methods, or (b) add a `ClientMethodHandler` port and implement `fs/read_text_file` / `terminal/*` behind it with the same approval and path-scrub rules as REQ-033. Default to (a) for v0.4.0 and record the decision in `docs/STATE.md`. Risk: some executors may refuse to start without a capability; probe with the stub and the OpenCode matrix row, and keep the negotiated result observable in `tracing`.

4. **Cancellation-safe permission and a real cancel path.** Hand `decide()` to a spawned task returning through a `oneshot`, so the pump keeps reading; make an owned-session actor with a bounded channel the eventual concurrency boundary (the current `&mut self` cannot be shared with a task). Send `session/cancel` and then `session/close` on run cancellation, outer timeout, or terminal-run detection; shorten the permission timeout below the 600 s prompt timeout; abort the stderr `JoinHandle` on shutdown. Risk: the actor refactor is the largest change and touches REQ-061 run semantics — stage it (oneshot first, actor second), treat externally visible cancel timing as a DEVIATION needing owner approval, and keep `kill_on_drop(true)` as the last-resort guarantee.

5. **Typed `AcpError` + in-module adversarial tests.** Add an internal enum (`Spawn`, `Handshake`, `Protocol`, `Timeout`, `LineCap`, `BadUtf8`, `AgentError { code, message }`) converted to `AppError::Unavailable` at the boundary while enriching `tracing` fields (so worker classification stays stable). Add `#[cfg(test)]` proptest cases for `read_line_bounded`: multiple lines per chunk, a line exactly at `MAX_LINE_BYTES`, cap overshoot, invalid UTF-8 split across chunks, empty/blank frames, and string ids. Risk: richer errors may tempt callers to change run classification; keep the conversion collapsing for now and add a separate ADR before exposing new variants.

## Explicit non-goals

No remote HTTP/WS ACP transport, no session persistence across turns (one subprocess per turn is ADR-030 accepted), no change to the compiled-in executor registry in `acp_provider.rs`, no new dependency (serde/tokio already present), no change to the explicit-attach REQ-061 rule, no auto-approval of permission requests.

## Suggested sequencing

2 (typed model) → 1 (single pump) → 3 (capability honesty) → 5 (errors + tests, woven through each step) → 4 (cancellation refactor, DEVIATION gate). Each step gated by `cargo fmt --check`, clippy `-D warnings`, the REQ-061 wire/golden replay, a missing-binary and timeout test, and unchanged `AppError` behavior at the provider boundary.
