# 0073 — apps/web/components/providers/app-providers.tsx — architecture lens (v0.4.0)

- Target: `before-m5` (v0.3.0-rc5), module `apps/web/components/providers/app-providers.tsx` (85 lines).
- Read-only review; no code edited. Related files read: `app/layout.tsx`, `lib/i18n.ts`, `lib/use-translation.ts`, `components/foundations/direction/direction.tsx`, `components/foundations/template-copy/template-copy.tsx`, `components/application/theme/theme-toggle.tsx`.
- Spec anchors: `spec/08-ui-ux.md` §8.x (i18n/RTL), REQ-057 (direction follows locale), `AGENTS.md` UI/UX policy (i18n from day one, one theme, BoardUI providers/tokens), `docs/UI.md` copy conventions.

## The composition today

`AppProviders` is intentionally thin, but the four cross-cutting concerns it is named for are *not* all composed here — they are split across four files that agree only by convention:

- **Direction/intl (here):** `useSyncExternalStore` reads `document.documentElement.lang`, seeded from the inline `BOOT_SCRIPT` in `layout.tsx`; the result is passed to BoardUI `DirectionProvider` (= React Aria `I18nProvider` + a `display: contents` boundary). `useTranslation()` then calls `useLocale()` from that provider and looks up `lib/i18n.ts::t()`. Locale flows correctly (CONFIRMED by reading the chain) — this part is sound and should be preserved.
- **Theme (not here):** theme is *not* a React provider. `layout.tsx::BOOT_SCRIPT` writes the `.dark` class from `localStorage["boma-theme"]`; `ThemeToggle` reads/writes `localStorage["boardui:theme"]` and dispatches `boardui:theme-change`; `useThemeMode()` re-reads the `.dark` class via another `useSyncExternalStore`. No context, DOM-coupled but functional.
- **BoardUI copy (not here):** `TemplateCopyProvider` is defined but **never mounted** anywhere in `apps/web` (CONFIRMED: the only references are its own definition). Every `useTemplateCopy()` call — theme toggle, settings, date picker, pagination, file upload, dashboard menus, agent-thinking — therefore returns its node unchanged. BoardUI template copy stays in source English even on a Hebrew page, despite the catalogue carrying `he`/`fr` strings.
- **Auth guard (here):** `UnauthorizedRedirect` installs one module-global 401 handler that `router.replace`s to `/sign-in?next=…`, inert on `/sign`, `/forgot`, `/reset` paths. Correct shape (set once at root, clear on unmount), but untested and uncomposed.

Consequently `AppProviders` is the natural, currently-missing composition root: one place where intl, direction, theme and the BoardUI copy contract meet, instead of four files that must be changed together.

## How it should evolve in v0.4.0

Keep `AppProviders` as the single client root under `<body>`; compose an explicit, ordered provider stack inside it and move the locale/theme *handshake* behind one typed contract. Do **not** introduce a second design system or duplicate the locale catalogue. Keep the server snapshots (`en`, `light`) so hydration stays warning-free with `suppressHydrationWarning` on `<html>`.

## Proposals

### 1. Mount `TemplateCopyProvider` wired to the catalogue (highest value)
Wrap children with `<TemplateCopyProvider translate={(s) => t(locale, reverseKey(s))}>` inside `AppProviders`, where `locale` is the value already read by `useSyncExternalStore`. This activates the ~12 `useTemplateCopy()` call sites so BoardUI copy follows REQ-057/i18n policy. `translateTemplateCopy()` already confines translation to a whitelist of text props and skips IDs/data/callbacks, so data and handlers stay intact. Risks: (a) it needs a source-English-string → catalogue-key map (GUESS — no such map exists today; the catalogue is keyed, not source-text keyed), so either add a small `sourceCopyKey` lookup or translate by value with an explicit dictionary and fall back to identity, never to a blank; (b) a new context value invalidates memoized `useTemplateCopy` consumers — check the INP budget on the dashboard; (c) an incomplete map silently leaves English, which is today's behavior, so this is a safe incremental rollout. Do not translate the `<pre>/<code>` islands or the glass toggle's literal black/white (already documented as intentional).

### 2. Unify the locale/theme handshake and its storage keys
The boot script reads `boma-theme`/`boma-locale`, while `ThemeToggle` writes `boardui:theme` — so a manual theme choice is not restored on reload (CONFIRMED by reading both files: they are different keys). Export the boot constants and `DEFAULT_LOCALE` from one shared module used by both `layout.tsx` and `AppProviders`, pick one storage key per concern (keep `boardui:theme` if BoardUI consumers depend on it; alias `boma-theme` on read for compatibility), and observe both `lang` and `dir` in the locale `MutationObserver`. Risks: (a) fixing the key is an externally visible preference change — record it in `docs/PARITY.md` as a DEVIATION or frame it as a defect fix in `spec/05-known-defects.md`; (b) the boot script must remain inline and parse-blocking to avoid a first-paint flash — only share constants, do not import a module into it; (c) adding `dir` to `attributeFilter` is harmless but must not re-run the `queueMicrotask` re-read loop.

### 3. Give the stack one typed composition contract
Define a small `AppLocaleProvider`/`AppThemeProvider` pair (or a single `useAppShell` hook) that owns the two `useSyncExternalStore` reads and exposes `locale`, `direction`, `theme`, `setLocale`. Order them explicitly: locale → `DirectionProvider` → copy provider → theme → `UnauthorizedRedirect` → children. Keep `applyTheme()`/`.dark` untouched so the theme toggle's View Transition reveal still works. Risks: (a) more context boundaries mean more re-renders on a locale flip — memoize provider values (`useMemo`) and keep the store subscriptions module-scope; (b) a client `setLocale` implies a locale switcher writing `boma-locale` + `lang` + `dir` together — that is a new feature outside the spec, so list it in `docs/STATE.md` as a proposal, do not ship it silently; (c) server snapshots must stay `en`/`light` regardless of the new context.

### 4. Validate locale at the boundary before it reaches intl
The raw `document.lang` value is fed straight to `I18nProvider` and to `t(locale, key)`. A manual `boma-locale=he-IL` yields RTL layout but no exact catalogue key → English copy for the whole app (GUESS — inferred from `SUPPORTED_LOCALES` and `t()`'s exact lookup). Normalize with `Intl.getCanonicalLocales` and match against `SUPPORTED_LOCALES` (prefix match, e.g. `he-IL` → `he`) in `AppProviders` before passing it down; let `DirectionProvider` receive the normalized BCP 47 tag. Risks: (a) changes what a hand-set locale produces — document the fallback in `docs/STATE.md`; (b) must keep `dir` consistent with the *normalized* locale, not the raw attribute; (c) adding `Intl.getCanonicalLocales` calls on the client is cheap but needs a try/catch for malformed tags.

### 5. Extract and test the unauthorized-redirect policy
Pull the 401 → sign-in mapping into a pure function `unauthorizedTarget(pathname, search, isAuthPath)` returning the `next` target, and add unit + Playwright coverage (name carries REQ id e.g. `it("REQ-0xx 401 returns to the original path")`, per AGENTS traceability). Keep `router.replace` (no sign-in history entry), the module-global handler set/clear, and the `/sign|/forgot|/reset` guard; consider making the guard list a named constant. Risks: (a) the module global is shared across app instances/HMR — the existing cleanup on unmount must be retained or tests leak handlers; (b) query-string preservation (`window.location.search`) and encoding must not change, or a signed-out member loses their place; (c) do not "fix" this by trusting client auth state — the server remains the only boundary.

## Explicit non-goals
No second design system, no BoardUI Pro dependency, no change to the server-refuses auth model, no hardcoded user-visible strings in the provider, no client-side role caching, and no locale switcher shipped without an ADR/STATE entry. The `.dark` class, `display: contents` direction boundary and module-scope store subscriptions stay as-is unless a measurement shows a regression.
