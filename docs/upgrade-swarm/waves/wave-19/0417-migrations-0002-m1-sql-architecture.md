Worker #417 · module `migrations/0002_m1.sql` (299 lines) · lens: architecture (schema decomposition,

## 1. Current structure (CONFIRMED)

- Lines 1-18 fix the contract: `boma.space_id` is the tenant setting (CI greps for it); a query
  without it sees nothing; `boma` holds helpers only. Line 19 pins `search_path = public` so a role
  named after a schema cannot capture the tables.
- Helpers (27-60): `current_space_id()` returns `current_setting('boma.space_id', true)::text`
  (NULL when unset → policies deny, fail-closed); `is_system()` is a single boolean
  `COALESCE(current_setting('boma.system_reason', true), '') <> ''`; `rfc3339()` renders UTC text
  because session expiry is compared as text.
- Global tables (70-113): `users`, `organizations`, `organization_members`, `sessions` — no RLS,
  membership checked by the app. Tenant tables (122-236): `spaces` (its own tenant, policy on `id`)
  plus 7 tables with `space_id`. Idempotency/fencing primitives are present: partial unique indexes
  on `(thread_id, client_nonce)` (186-188, 211-213), `next_message_seq`/`next_event_seq` (162-164),
  `lease_fence` (201-203).
- RLS: `spaces` policy written literally (249-254); the other 7 generated by a `DO` block
  (256-280) with `ENABLE` + `FORCE` and `USING`/`WITH CHECK` = tenant match **OR** `is_system()`.
- All settings are transaction-local: `set_config(..., true)` in `crates/infra/src/tenant.rs:120-126`
  — no pooled-connection leakage (CONFIRMED strength).

## 2. Architectural risks

- **O1 — policy coverage is convention, not enforced (CONFIRMED).** The expression is duplicated:
  once for `spaces`, once in the `DO` block. At least 15 later migrations copy the pattern again
  with drift: `0038`/`0044` use explicit `_tenant_isolation` policies, `0056` uses `_tenant` +
  `FOR ALL`, and `0005`/`0009`/`0013`/`0017`/`0025`/`0026` repeat the `DO` block. ADR-002's
  consequence promises a test enumerating `space_id` tables and asserting each has a policy; grep
  over `tests/` and `crates/` found **no such test**. A new tenant table can ship unprotected and
  CI stays green.
- **O2 — the system bypass is one bit at the DB layer (CONFIRMED shape, GUESS impact).** The closed
  enum lives only in Rust (`crates/domain/src/tenancy.rs::SystemReason`, 8 variants) plus a CI grep.
  SQL accepts *any* non-empty `boma.system_reason` as a full cross-tenant read/write grant for every
  policy. The path is routine, not exceptional: 33 `as_system` vs 37 `in_space` call sites; reasons
  include `Authentication`/`AccountExport` used for ordinary membership lookups
  (`stores/spaces.rs:93-117,241+`). A copy-pasted or injected string bypasses RLS with no DB signal.
- **O3 — the global half of the boundary has no DB guard (CONFIRMED).** Users/orgs/members/sessions
  rely entirely on app-level membership checks; bootstrap reads run as system with a *global*
  reason carrying no space scope. The DB cannot tell a legitimate bootstrap read from a leak.
- **O4 — two clocks, weak invariants (CONFIRMED).** M1 timestamps are app-supplied text (44-48),
  while later migrations/stores use DB `now()` (e.g. `0044` defaults). No `updated_at` on M1 tables
  and no CHECK on `next_*_seq` or `lease_fence`; ordering/expiry can drift with clock skew.

## 3. Additive upgrades for v0.4.0 (value order)

- **A. RLS-coverage conformance test (low risk, highest value).** Add an integration test that
  reads `pg_class`/`pg_policies`: every `public` base table with a `space_id` column must have
  `relrowsecurity`, `relforcerowsecurity`, and a policy whose qual references
  `boma.current_space_id()`. Add an optional `boma.assert_tenant_coverage()` helper (new function).
  *Risk:* match on expression, not policy name (`_tenant` vs `_tenant_isolation`); filter
  `relkind IN ('r','p')` and keep an allow-list of intentional global tables to avoid false positives.
- **B. DB-side system-reason allow-list (medium risk; defense-in-depth for D-09).** Additive step:
  create `boma.system_reasons` seeded with the 8 `SystemReason::as_str()` wire values and a new
  `boma.is_allowed_system_reason()` helper. **Do not** change `is_system()` here — a later
  ADR-gated migration adopts the check. Prefer a `boma.system_reason` enum type over a lookup table
  to avoid a catalog read per policy evaluation. *Risk:* SQL/Rust enum drift (new variant = two
  edits); tightening an escape hatch is a behavior change → ADR + `docs/PARITY.md` DEVIATION if any
  external caller sets a custom reason; `ALTER TYPE ... ADD VALUE` caveats inside transactions.
- **C. Canonical policy helper to stop cross-migration drift (low-medium risk).** Add
  `boma.apply_tenant_rls(p_table text)` that enables + forces RLS and creates the standard
  `<table>_tenant_isolation` policy; use it for all future tenant tables. *Risk:* must stay
  SECURITY INVOKER and schema-qualified; normalizing the 3 divergent `0056` policies later is
  **not** additive (renames break grants/tests) and needs its own ADR.
- **D. DB-side membership helper for the global surface (medium risk).** Add
  `boma.is_space_member(space_id, user_id)` SECURITY DEFINER with a fixed `search_path`, so future
  global reads can check membership at the DB boundary instead of trusting app code; keep
  `as_system` bootstrap unchanged. *Risk:* grants/ownership on SECURITY DEFINER; two-layer logic can
  diverge; broad EXECUTE could expose a cross-space membership oracle — grant to the app role only.
- **E. Timestamp and sequence invariants (low-medium risk).** Additive migration: `updated_at`
  columns + a `boma.touch_updated_at()` trigger on mutable tables, and CHECK constraints
  (`next_message_seq >= 1`, `next_event_seq >= 1`, `lease_fence >= 0`). *Risk:* backfill of
  `updated_at`; a CHECK may fail on legacy rows (GUESS — verify data first); triggers under FORCE
  RLS must be tested with two spaces before rollout.

## 4. Deferred / non-goals

No change to published names, columns or wire formats (parity); no drop/rename; no in-place edit of
`current_space_id()` or `is_system()` in this wave; no ADR decisions made here — B-D need owner
sign-off. A-D mostly add objects; A is the only one that directly discharges an existing ADR-002
obligation and is safe to ship first.
