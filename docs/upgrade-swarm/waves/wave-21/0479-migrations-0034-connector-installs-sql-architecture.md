## Summary (current structure, CONFIRMED)

0034 creates one table `connector_installs` keyed `PRIMARY KEY (space_id, connector_id)`: `auth_kind text CHECK (auth_kind IN ('none','api_key'))`, `sealed_credential bytea`, `sealed_credential_nonce bytea`, `status text DEFAULT 'connected' CHECK (status IN ('connected','revoked'))`, `created_at`/`updated_at timestamptz DEFAULT now()`, with `space_id … REFERENCES spaces(id) ON DELETE CASCADE`. It then inlines `ENABLE`/`FORCE ROW LEVEL SECURITY` and a `connector_installs_tenant_isolation` policy with `USING/WITH CHECK (space_id = boma.current_space_id() OR boma.is_system())`. Credentials are sealed under the per-space DEK (ADR-020); the catalogue of connectors stays in code (`boma_domain::builtin_connectors`), not in SQL.

## Architectural findings

- **A1 (HIGH, CONFIRMED):** the isolation predicate is duplicated inline here and in 0026/0029/0035 (0026 even wraps a one-element `DO $$ … FOREACH` loop). `boma.is_system()` is copy-pasted into a table that holds secrets. One hardening change must be applied by hand N times or the tables drift (ADR-002 consequences).
- **A2 (HIGH, CONFIRMED):** the credential envelope is untyped — just `sealed_credential` + `sealed_credential_nonce`, with no `format_version`, `key_id`, `purpose` or AAD columns. There is no domain separation and no way to add an envelope format incrementally under additive-only; worker #463 reports the identical gap in `bot_secrets`.
- **A3 (HIGH, CONFIRMED):** the System escape hatch is dangerous on this table. Wave-15 #339 established that RLS *lifts* the filter for System, so `revoke(System, id)` is a cross-space UPDATE and `connected_credential(System, id)` can read an arbitrary space's secret. The store rejects System on `install` only; the DB still grants the bypass to a secrets table.
- **A4 (MED, CONFIRMED):** status/auth_kind are free-text CHECKs whose literals are repeated in the migration and in the store's SQL (wave-15 #339 U2). The DB cannot reject a connector_id absent from the code catalogue (no FK — expected given the code-catalogue design), and a stored `auth_kind` is never cross-checked against the catalogue on read, so catalogue drift leaves silently stale rows.
- **A5 (MED, CONFIRMED):** revoking keeps the ciphertext. `status='revoked'` only flips a flag; `sealed_credential`/nonce persist forever, and there is no `revoked_at` and no lifecycle cleanup — data-minimization debt on a secret store. No `octet_length` checks exist on the crypto columns, so a wrong-size nonce/tag fails only at decrypt time.
- **A6 (LOW, CONFIRMED + GUESS):** no `IF NOT EXISTS`/idempotency guards (latent, since migrations run once), and `updated_at` is maintained only by the store's explicit SQL — no DB trigger catches a future writer that forgets. The spec data model lists an "account ref" for connections (GUESS: whether REQ-032 needs it); adding it is a feature question for `docs/STATE.md`, not a silent change.

## Concrete upgrades (v0.4.0, all additive)

1. **P0 — Shared tenant-isolation helper for future migrations.** New migration defines `boma.tenant_isolation(space_id text)` and a helper applying `ENABLE`/`FORCE RLS` plus `DROP POLICY IF EXISTS …; CREATE POLICY … tenant_isolation(space_id)`. New tenant tables call it; leave 0034/0026 bytes untouched; replace duplicated policies only in a later sweep. *Risks:* the predicate must preserve `boma.is_system()` and FORCE semantics exactly or system paths break; a `SECURITY DEFINER` helper needs a pinned `search_path`; centralizing raises the blast radius of one bug — cover with an RLS test over all tenant tables.

2. **P0 — Remove the System bypass for this secrets table.** New migration swaps 0034's policy for one without `OR boma.is_system()` (keep `space_id = boma.current_space_id()` only), coordinated with store worker #339 U1 (System-context guard in Rust). *Risks:* any legitimate admin/maintenance path using the bypass breaks — GUESS whether space-deletion or audit paths rely on it; verify `ON DELETE CASCADE` still works under FORCE RLS before landing; tightly scoped internal change, but confirm it is not externally visible before deciding on a `docs/PARITY.md` entry.

3. **P1 — Self-describing credential envelope (nullable-first).** New migration adds nullable `credential_format smallint DEFAULT 0`, `credential_key_id bytea`, `credential_purpose text` with a `credential_format IN (0,1)` CHECK; the app writes v1 with AES-GCM AAD = `format ‖ key_id ‖ purpose ‖ space_id ‖ connector_id`, reads v0 for legacy rows, and a *later* migration backfills then sets `NOT NULL`. *Risks:* a persisted data-format change is a DEVIATION → `docs/PARITY.md` + owner approval (AGENTS.md); dual-read doubles the test matrix; wrong AAD makes data unreadable — land test-first with a legacy round-trip golden, coordinated with workers #339/#463 and the `space_keys`/`secret_box` code. Never persist plaintext.

4. **P1 — Lifecycle cleanup on revoke.** New migration adds nullable `revoked_at timestamptz`, nulls `sealed_credential`/nonce on existing `status='revoked'` rows, then adds `CHECK (status <> 'revoked' OR sealed_credential IS NULL)` (backfill first, `NOT VALID` then `VALIDATE`); the revoke write path sets `revoked_at` and clears the ciphertext. *Risks:* destroys revoked ciphertext (currently unreadable because `connected_credential` filters `status='connected'`, so double protection exists) — GUESS whether any golden expects it to remain; app write-path change and default must keep existing rows migrating cleanly; do not log the value.

5. **P2 — Crypto-column integrity + `updated_at` maintenance.** New migration adds `CHECK (octet_length(sealed_credential_nonce) = 12)` and `CHECK (octet_length(sealed_credential) >= 16)` (`NOT VALID`, audit, then `VALIDATE`), plus a trigger maintaining `updated_at` on UPDATE so manual SQL paths cannot forget it. *Risks:* sizes must match `secret_box.rs` (worker #463 reports 12-byte nonces CONFIRMED there; GUESS here) — verify against the real crypto code and DB; a stray row fails VALIDATE, so gate on the audit query; the trigger can conflict with the store's explicit `updated_at = now()` (choose one source of truth); GUESS if any legacy writer used different sizes.
