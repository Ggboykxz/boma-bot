# M15.1 — Web Push core implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development if the owner picks it) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Follow project rules in `AGENTS.md`: TDD, migrations never edited, REQ id in the test name, fmt + clippy `-D warnings` + workspace tests + `trace --max-missing 9` before every push.

**Goal:** Boma Bot can reach a member with a content-free Web Push notification when their run parks on a person (approval/question) or when that run finishes (completed or failed), behind a per-(space, member, bot) policy with a daily cap, delivered best-effort by the worker.

**Architecture:** Server-side subscriptions stored per (space, member, endpoint); policy rows per (space, member, bot); a `notifications` RPC namespace the web calls to subscribe and toggle a bot's policy; a `NotificationStore` port (PG + in-memory double); a small `push` module in `crates/app` that encrypts with RFC 8188 (AES-128-GCM) and signs VAPID via the `web-push` crate's `build_request`, posting to the endpoint over the existing `reqwest` (rustls) HTTP client; worker hooks at the three transition sites.

**Tech Stack:** Rust (Tokio, sqlx PG), `web-push = { version = "0.11", default-features = false }`, `reqwest` (already in the workspace), Next.js 15 static export, Playwright, Postgres RLS.

**Spec:** `/home/user/myapp/rebuild-workspace/.worktrees/before-m5/docs/superpowers/specs/2026-11-15-m15-push-notifications-design.md`

## Global Constraints

- REQ-064 (new in this milestone) is the spec floor. Ids in test names; `trace --max-missing 9` stays at 3 missing (REQ-049, REQ-056, REQ-061).
- Migrations are additive only. `0056_notifications.sql` only; never edit an existing migration.
- All new tables: `space_id` FK → `spaces(id) ON DELETE CASCADE`, `user_id` FK → `users(id) ON DELETE CASCADE`, `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY`, policies shaped `space_id = boma.current_space_id() OR boma.is_system()`.
- Push payloads never carry conversation content: serialized keys are exactly `{v, kind, title, tag, url}`.
- Push is best-effort: a failing/dead push never fails a run, never panics, never becomes an RPC/HTTP 5xx.
- Missing VAPID = feature disabled (`status` answers `enabled: false`). Malformed VAPID = fail-fast at boot (typed config, same rule as `BOMA_MASTER_KEY`).
- No secrets in the logs or in payloads; webhook/endpoint values never appear outside the store.
- `cargo fmt --all`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, web `typecheck` + `lint` + `build` + affected Playwright specs + `trace_check.py spec . --max-missing 9` must all pass before pushing.

## Review Focus

1. **Cap boundary** — the send at `count < daily_cap` goes through, the one at `count == daily_cap` is skipped; cap counted per UTC day per (space, user, bot). Task 5 pins it with `req_064_daily_cap_is_enforced_at_the_boundary`.
2. **Dead endpoints** — permanent (404/410/401/403) ×3 deletes the subscription row; transient (5xx/network) only bumps the counter and resets on success. Task 5 pins it with `req_064_three_permanent_failures_delete_the_subscription`.
3. **SSRF in `notifications.subscribe`** — `http://192.168.1.10/…`, `https://169.254.169.254/…`, or any non-HTTPS endpoint refused with a rule error; public HTTPS accepted. Task 6 pins it with `req_064_subscribe_rejects_private_or_plain_http_endpoints` (reuse the `net_safety` host-screening helpers if they already expose one).
4. **Push never sinks a run** — an unreachable endpoint (timeout/500) during waiting-push leaves the run parked and the card answerable. Task 5 pins it with `req_064_a_wedged_push_leaves_the_run_parked`.
5. **Replay does not double-notify** — `park_tool_calls` is idempotent; the push fires once per card created. Task 5 pins it with `req_064_repark_after_steering_notifies_once_per_card`.

```markdown
### REQ-064 — Web Push notifications (MUST)
A member can subscribe the browser to push notifications for a space, per bot. The server may
push content-free notifications when the member's run parks waiting on a person (approval or
question card), and when that run completes or fails; pushes never carry conversation content.
Pushes follow the member's per-bot policy and a per-(space, member, bot) daily cap,
and a dead subscription is deleted after repeated permanent failures.
- Given an opted-in member with no waiting runs, when their run completes, then a push naming
  neither the thread nor tool arguments arrives, and following it opens the thread.
- Given a member whose daily cap is already reached, when the run would notify them, then no push
  is sent and the run is unaffected.
- Rationale: the bot is only as useful as its reach when nobody has the app open.
```

```sql
-- REQ-064 (improvement program): Web Push subscriptions and the per-bot policy.
CREATE TABLE notification_subscriptions (
    id text PRIMARY KEY,
    space_id text NOT NULL REFERENCES spaces (id) ON DELETE CASCADE,
    user_id text NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    endpoint text NOT NULL,
    p256dh text NOT NULL,
    auth_secret text NOT NULL,           -- 'auth' is a reserved word risk in some clients; stored verbatim
    user_agent text,
    fail_count integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT notification_subscriptions_keys_not_empty
        CHECK (length(btrim(endpoint)) > 0 AND length(btrim(p256dh)) > 0 AND length(btrim(auth_secret)) > 0)
);
CREATE UNIQUE INDEX notification_subscriptions_owner ON notification_subscriptions (space_id, user_id, endpoint);
CREATE INDEX notification_subscriptions_by_owner ON notification_subscriptions (space_id, user_id);
ALTER TABLE notification_subscriptions ENABLE ROW LEVEL SECURITY;
ALTER TABLE notification_subscriptions FORCE ROW LEVEL SECURITY;
CREATE POLICY notification_subscriptions_tenant ON notification_subscriptions
    FOR ALL
    USING (space_id = boma.current_space_id() OR boma.is_system())
    WITH CHECK (space_id = boma.current_space_id() OR boma.is_system());

CREATE TABLE notification_policies (
    space_id text NOT NULL REFERENCES spaces (id) ON DELETE CASCADE,
    user_id text NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    bot_id text NOT NULL REFERENCES bots (id) ON DELETE CASCADE,
    notify_waiting boolean NOT NULL DEFAULT true,
    notify_completed boolean NOT NULL DEFAULT false,
    daily_cap integer NOT NULL DEFAULT 20 CHECK (daily_cap >= 0),
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (space_id, user_id, bot_id)
);
ALTER TABLE notification_policies ENABLE ROW LEVEL SECURITY;
ALTER TABLE notification_policies FORCE ROW LEVEL SECURITY;
CREATE POLICY notification_policies_tenant ON notification_policies
    FOR ALL
    USING (space_id = boma.current_space_id() OR boma.is_system())
    WITH CHECK (space_id = boma.current_space_id() OR boma.is_system());

CREATE TABLE notification_log (
    id text PRIMARY KEY,
    space_id text NOT NULL REFERENCES spaces (id) ON DELETE CASCADE,
    user_id text NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    bot_id text NOT NULL REFERENCES bots (id) ON DELETE CASCADE,
    kind text NOT NULL CHECK (kind IN ('waiting', 'completed')),
    sent_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notification_log_by_day ON notification_log (space_id, user_id, bot_id, sent_at);
ALTER TABLE notification_log ENABLE ROW LEVEL SECURITY;
ALTER TABLE notification_log FORCE ROW LEVEL SECURITY;
CREATE POLICY notification_log_tenant ON notification_log
    FOR ALL
    USING (space_id = boma.current_space_id() OR boma.is_system())
    WITH CHECK (space_id = boma.current_space_id() OR boma.is_system());
```

**Interfaces:** implementation mirrors `PostgresSignInStore` (RETURNING + `boma.rfc3339`).
`note_failure` does one upsert-by-id with the three-strikes rule inline in SQL: increment, and
`DELETE … WHERE id = $1 AND fail_count >= 3` returning whether a delete happened — one transaction
via `tenant::in_space`. `count_today` filters `sent_at >= date_trunc('day', now() AT TIME ZONE 'utc')`.

  5. **Never propagate**: any Err in steps 2–4 is `tracing::warn!` and Ok(()).
- Payload `serde_json::json!({ "v": 1, "kind": kind.as_str(), "title": title, "tag": tag, "url": url })` — `tag` = `"run:<run_id>"`, `url` = `"/app/<bot_id>/"`. Keys exactly those five.
